# ADR-002 · 建立"创业者外脑"与 docs 治理层（跨窗口不断线）

- 状态：Accepted
- 日期：2026-09-22
- 决策者：持有人（AI 提方案并落地）

## 背景
持有人会在多个豆包任务窗口、微信、实地接触中零散推进创业事项，痛点是每个新窗口都要重讲背景、
资料和想法散落、第二曲线念头多容易发散。桌面姊妹仓 `astock-quant` 已跑通一套"外脑 + HANDOFF +
新窗口接手 + 跨窗口增量采集"机制，可借鉴；但那是纯调研/文档型项目原本只有六槽位，需要决定是否加治理层。

## 决策
1. 在六槽位之外新增**轻量 `docs/` 治理层**，承载外脑运转规则，不放结论成品（仍在 01）与原始素材（仍在 09）：
   - `创业者外脑.md`（宪章）、`创业者画像.md`（角色画像）、`HANDOFF.md`（活日志+当前纠结+想法停车场）、
     `新窗口接手开场白.md`（固定接手 SOP + 冷启动六问）、`外脑喂养SOP.md`（五类输入归宿与周节奏）、`README.md`（地图）。
2. **外脑服务对象=持有人本人**（区别于 astock-quant 克隆外部操盘手）；画像分两版：
   可公开职业画像明文随仓，含年龄/家庭/资金/在职出走的完整版放本地 `创业者画像_私有.md`（gitignore）。
3. 新增 `09/跨窗口思考/` 收件箱收本人其它窗口产出（`inbox/` 不入库）；与既有 `09/同业来件/`（他人来件）分工。
4. 固化两类触发机制写入 AGENTS：①"开新任务窗口"→ 老窗口收口 + 选文件夹 + 标准句 + 六问验收；
   ②转发资料/新想法 → 按喂养 SOP 当场判归宿，想法先停 HANDOFF §4 停车场、第二曲线默认挂起。
5. 跨窗口原话找回用已装技能 `local-trajectory-recall`（本机、原文不入 git）；本项目不照搬 astock-quant 的
   扫描脚本与体检脚本（纯文档项目、量小），改为人工一致性自查，日后量大再议。

## 放弃的备选
- 把外脑规则塞进根 README/AGENTS：会让入口文件臃肿，且 HANDOFF 活日志、画像、SOP 职责不同，混在一起难维护。
- 完整移植扫描脚本/launchd/体检脚本：对纯文档、单人、低频项目过重，先用技能 + 人工节奏。
- 把完整敏感画像也推公开远程：违反 security-baseline 个人信息红线；在仓库转私有决策拍板前只留本地。

## 后果与待验证
- 新窗口凭仓库路径即可冷启动、转发资料有确定归宿、想法不挤占第一年主线；代价是每周 15 分钟维护纪律。
- 待持有人拍板：仓库是否由 public 转私有（转私有后可把 `_私有` 画像并入、inbox 随仓）；8 问答案补全后画像升版并出 90 天行动包。
